# Telescode onboarding tour instructions

목적은 새 개발자가 저장소를 처음 읽을 때 어디서 시작하고 다음에 무엇을 읽어야 하는지 이해하는 것이다.
투어는 이동과 정지 시간을 포함해 최대 60초, 최대 8개 지점이다. 사용자에게 계획을 보여주고 정확한 revision의 승인을 받은 뒤 렌더링한다. 승인 폼을 에이전트가 대신 제출하지 않는다.

## 조사와 순서

1. `get_project_overview`와 `get_reading_tour_order`로 reading sequence 결과를 확인한다.
2. 파일은 `fileRank` 오름차순으로 방문한다. 클래스는 해당 파일 뒤에서 `localRank` 순서로 방문한다. 함수/멤버/소스 줄은 방문하지 않는다.
3. 시간에 맞춰 상위 항목 일부를 선정하되 결과의 상대 순서를 바꾸지 않는다. 시작과 끝의 repository 개요는 허용한다. 디렉터리는 필요한 위치 맥락만 제공한다.
4. reading sequence가 없으면 임의의 파일 순서를 만들지 말고 분석 알고리즘 실행 후 `analyze` 스냅샷을 요청한다. 클래스 local rank가 없다면 해당 파일의 맥락에서만 설명한다.
5. `inspect_node`의 실제 관계와 점수로 설명을 뒷받침한다. 높은 순위/복잡도만으로 런타임 진입점이나 비즈니스 역할을 단정하지 않는다.

## 온보딩 설명

- 첫 지점: 저장소의 큰 구조와 이번 투어의 읽기 경로를 소개한다.
- 각 파일/클래스: 위치 → 확인 가능한 역할/책임 → 연결된 구성요소 → 다음 읽을 대상 순서로 설명한다.
- 신규 개발자가 모르는 약어와 내부 식별자를 풀어 설명한다. 점수 나열은 근거 패널에 맡긴다.
- 소스 내용이 제공되지 않았으면 동작을 추측하지 않는다. 그래프가 보여주는 구조와 관계에 집중한다.
- 자막은 짧은 문장 1–2개로 작성한다. 한 번에 많은 개념을 넣지 않고 충분한 읽기 시간을 배정한다.
- 마지막 지점: 기억할 구조와 다음에 읽을 파일을 정리한다.

## 화면과 결과

- 읽기 경로 패널에 현재 위치와 다음 지점을 표시한다. 대상은 nodeId로 focus하고 이동 후 정지한다.
- `preview_tour_frame`으로 주요 정차 화면을 확인한 뒤 사용자에게 계획, 자막, 근거, 예상 시간을 제시한다.
- 결과는 무음 WebM + 별도 VTT이다. 설명 자막을 영상에 합성하지 않는다.
- 재생 페이지의 VTT 글자 크기는 브라우저 기본 크기의 50%이다. 외부 플레이어 글자 크기는 해당 플레이어 설정에 따른다.
